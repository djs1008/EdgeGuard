# EdgeGuard 系统架构

## 1. 文档状态

- 阶段：阶段 0（初始化）
- 状态：概念架构草案
- 用途：描述系统边界、模块职责、主要数据流和待确认决策

本文不包含已实现设计；所有接口和技术选择均需在后续阶段验证。

## 2. 系统上下文

```text
被测旋转设备
   │ 振动 / 电流 / 温度
   ▼
STM32 采集与边缘推理节点
   │ 遥测 / 推理 / 告警 / 设备状态
   ▼
Orange Pi 网关
   │ API / 实时与历史数据
   ▼
Web 仪表盘
```

## 3. 逻辑分层

### 3.1 硬件与采集层

- 被测对象：130 直流电机和 12 V 风扇；
- ADXL345：采集三轴加速度；
- INA219：采集电压、电流与功率相关数据；
- DS18B20：采集温度；
- MOSFET 与 XL4015：在安全范围内控制和供电。

### 3.2 STM32 实时层

规划职责：

- 传感器驱动与确定性采样；
- 时间戳、缓冲和数据质量统计；
- 滤波、分窗、时域/频域特征；
- TinyML 分类与异常检测；
- 本地 LED、蜂鸣器或显示告警；
- 与网关通信。

### 3.3 Orange Pi 网关层

规划职责：

- 设备连接和协议解析；
- 数据持久化与查询；
- API、日志、告警和设备状态；
- 向 Web 仪表盘提供数据。

### 3.4 数据与模型层

规划职责：

- 原始数据和会话元数据管理；
- 数据质量检查、清洗、分窗和特征提取；
- 分类与异常检测模型训练；
- 评估、量化、导出和模型版本管理。

### 3.5 展示层

规划职责：

- 展示设备连接状态；
- 展示振动、电流和温度趋势；
- 展示分类、置信度、异常分数和告警；
- 查询历史事件及关联版本。

## 4. 初步数据流

1. 传感器产生原始测量值；
2. STM32 依据时间基准采集并写入有界缓冲区；
3. 信号处理模块形成模型输入或诊断特征；
4. 推理模块输出分类和异常分数；
5. 告警模块执行本地反馈；
6. 通信模块发送遥测、推理结果和系统健康信息；
7. Orange Pi 解析、校验、存储并向 API 发布；
8. 仪表盘查询和展示实时或历史信息。

## 5. 关键设计原则

- STM32 在断开网关后仍应保持采集和本地告警能力；
- 所有高频数据路径采用有界内存，避免不可控动态分配；
- 驱动层不直接包含模型或界面逻辑；
- 协议必须版本化，并具备长度、序号和完整性校验；
- 训练与 MCU 前处理必须使用一致参数和黄金向量；
- 数据集按独立会话划分，避免同源窗口泄漏；
- 硬件配置和性能数字必须来自资料或实测，不凭空假定。

## 7. 待决策记录

后续应通过架构决策记录（ADR）明确：

- ADXL345 使用 I²C 或 SPI；
- 采样率、窗口长度、重叠比例和时间同步；
- 串口帧格式、CRC 类型和最大载荷；
- 首版是否使用 FreeRTOS；
- 网关数据库与前端技术栈；
- 模型类型、量化方法和 MCU 推理运行时；
- 原始高频数据的保存和异常事件回溯策略。
