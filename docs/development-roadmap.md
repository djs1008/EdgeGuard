# EdgeGuard 开发路线图

## 1. 路线图原则

- 每个阶段必须产生可运行、可验证或可审查的交付物；
- 所有模块先单独验证，再逐步集成；
- 先建立可靠数据，再训练模型；
- 先完成最小闭环，再加入 RTOS、PCB、OTA 等进阶能力；
- 未完成或未实测的功能不得在 README 和作品集中宣称已经实现。

## 2. 里程碑

### 阶段 0：项目结构初始化（当前阶段）

目标：建立目录、README、需求、架构、路线图、测试计划和忽略规则。

完成条件：

- 指定目录均存在；
- 空目录由 `.gitkeep` 保留；
- 文档明确当前仅为规划；
- 未生成业务代码和依赖。

### 阶段 1：板级启动与调试链路

目标：核对 STM32F407VGT6 板卡资料，完成供电检查、ST-Link 下载、LED、串口和基础定时器验证。

计划交付：板级启动记录、引脚表、构建/下载说明、启动自检固件。

### 阶段 2：传感器独立验证

目标：按 ADXL345、INA219、DS18B20 顺序逐个接入并校准。

计划交付：独立驱动、错误处理、主机测试和实机校准记录。

### 阶段 3：统一采集与串口数据流

目标：建立多速率采集、缓冲、时间戳、数据质量统计和版本化通信协议。

计划交付：协议规范、STM32 编码端、主机解析端、串口采集与可视化工具。

### 阶段 4：实验设计与数据集

目标：定义安全、可复现的正常和故障工况，按独立会话采集、标注和检查数据。

计划交付：数据集卡、元数据规范、质量报告、数据划分清单。

### 阶段 5：信号处理与离线模型

目标：建立规则基线、特征模型和轻量模型，完成分类与异常检测评估。

计划交付：可复现训练流程、模型卡、混淆矩阵、异常检测指标和错误分析。

### 阶段 6：STM32 TinyML 部署

目标：量化并部署冻结模型，保证主机与 MCU 前处理一致。

计划交付：模型导出流程、黄金向量测试、Flash/RAM/延迟和精度差异报告。

### 阶段 7：Orange Pi 网关与仪表盘

目标：实现稳定接收、持久化、API、实时/历史展示和告警查询。

计划交付：网关服务、数据库 schema、API、最小 Web 仪表盘和部署说明。

### 阶段 8：系统可靠性与工程化

目标：加入故障恢复、看门狗、背压、长期运行测试和异常事件回溯；在确有需要时迁移 FreeRTOS。

计划交付：故障注入报告、稳定性报告、资源水位和异常黑匣子记录。

### 阶段 9：V1.0 与作品集

目标：冻结演示版本，整理真实可复现的技术证据和作品集材料。

计划交付：完整 README、测试与性能报告、演示视频、项目复盘和简历描述。

## 3. 后续候选能力

以下能力不属于当前阶段，也不应阻塞 V1.0：

- 自定义 PCB 与外壳；
- 多设备、MQTT、CAN 或 RS485；
- 模型安全更新或固件 OTA；
- 麦克风和声音特征；
- Docker、CI 和硬件在环自动测试；
- 设备权限和远程部署。
