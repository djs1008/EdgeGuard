# EdgeGuard 需求说明

## 1. 文档状态

- 阶段：阶段 0（初始化）
- 状态：草案
- 用途：定义项目目标、范围、约束和可验收需求

本文件当前只建立需求骨架。标为“规划”的能力尚未实现。

## 2. 项目目标

EdgeGuard 计划构建一个可离线工作的旋转设备状态监测节点，通过振动、电流和温度数据完成状态识别与异常检测，并将数据发送到 Orange Pi 进行存储、查询和可视化。

## 3. 用户与使用场景

### 3.1 目标用户

- 项目开发者与测试人员；
- 查看设备健康状态的演示用户；
- 评估项目工程能力的面试官或作品集读者。

### 3.2 初步使用场景

- 监测 130 直流电机或 12 V 风扇的正常运行状态；
- 在安全、受控条件下模拟不平衡、松动、过载等状态；
- 在断网条件下由 STM32 本地检测异常并告警；
- 在 Orange Pi 上查看历史数据和告警记录。

## 5. 非功能需求

| 编号 | 类别 | 需求草案 |
|---|---|---|
| NFR-001 | 安全 | 电机堵转、过流和异常温升测试必须受限、短时且有人看护 |
| NFR-002 | 实时性 | 采集、处理和通信不应导致不可接受的丢样；具体阈值待实测确定 |
| NFR-003 | 可靠性 | 传感器或通信故障不得导致系统永久阻塞 |
| NFR-004 | 可测试性 | 协议、数据处理和模型前处理应提供主机侧自动测试 |
| NFR-005 | 可复现性 | 数据、配置、训练环境、模型和固件版本应可追踪 |
| NFR-006 | 可维护性 | 驱动、业务、信号处理、推理和通信应保持清晰边界 |
| NFR-007 | 资源约束 | 固件必须记录并满足 STM32F407 的 Flash、RAM 和时延预算 |
| NFR-008 | 数据质量 | 训练/验证/测试应按独立采集会话划分，避免窗口泄漏 |

## 6. 硬件约束

- 主控：STM32F407VGT6 Type-C 核心板；
- 网关：Orange Pi 3B；
- 传感器：ADXL345 ×2、INA219 ×2、DS18B20；
- 被测对象：12 V 两线风扇、130 有刷直流电机；
- 执行/供电：MOSFET 模块、XL4015、12 V 2 A 适配器；
- 调试：ST-Link；
- 具体引脚、地址、模块分流电阻、板载外设和电气参数必须依据实物与资料确认。

## 7. 当前非目标

- 本阶段不实现任何驱动或业务代码；
- 首版不要求声音采集、云端部署、多设备管理或 OTA；
- 不使用大语言模型替代传感器算法完成故障判定；
- 在原型功能稳定前不设计最终 PCB。

## 8. 待确认事项

- 核心板原理图、板载 LED 和时钟配置；
- 两块 ADXL345、INA219 模块的具体版本和电气参数；
- 首版使用 I²C 还是 SPI 连接 ADXL345；
- 设备转速范围和目标采样率；
- STM32 与 Orange Pi 的物理通信方式和波特率；
- V1.0 的模型指标、丢帧率、时延和稳定运行验收阈值。
